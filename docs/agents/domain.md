# Domain docs

This repository uses a single-context domain documentation layout.

## Before exploring

- Read root `CONTEXT.md` when it exists.
- Read relevant ADRs under `docs/adr/` when they exist.
- Proceed silently when either location is absent. Create domain documentation lazily through the domain-modeling workflow when a real term or decision is resolved.

## Vocabulary

Use terms defined in `CONTEXT.md` consistently in issues, proposals, tests, and code. Reconsider undefined synonyms or record a genuine terminology gap for domain modeling.

## Decisions

Surface conflicts with an existing ADR explicitly instead of silently overriding the recorded decision.
